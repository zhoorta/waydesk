Multi-user Linux desktops, over RDP or in a browser.

Every account on a Debian 13, Ubuntu 26.04, Arch or Fedora server gets its own desktop session, which keeps running when the user disconnects. People connect with the Windows App, Remmina or any RDP client, or sign in to the portal and open the desktop in a browser. Install from a signed apt, pacman or dnf repository.

install–□✕
$ curl -fsSLO https://waydesk.dev/apt/waydesk-repo.deb
$ sudo apt install ./waydesk-repo.deb
$ sudo apt update
$ sudo apt install waydesk
$ sudo waydesk-setup-admin

The portal: a browser, and several servers

RDP needs a client. The optional portal needs only a browser, and it is also where an administrator looks after more than one server. It is a package of its own (waydesk-portal), so a server that only wants RDP carries no web server. Install and use it

browser–□✕

The desktop in a browser

Sign in to a page and the session opens in the tab: H.264 decoded by the browser, keyboard, mouse, text and picture clipboard, and the window size follows the tab. An RDP client holds up better on a bad link.

servers–□✕

One portal, several servers

Each server runs a small agent that dials out to the portal, so the portal needs no way into it. Servers are added with a one-hour join code and the portal’s certificate pin.

people–□✕

People and accounts

An administrator assigns a person to servers and the portal makes the account on each. A person can also make an app password for an RDP client, and an authenticator code can be required at sign-in.

admin–□✕

Per-server administration

Overview with sessions, memory, CPU and GPU; accounts; sessions with an End button; the audit log. The Servers list shows every machine at a glance, and a server that stops answering is flagged in about 12 seconds.

Pick the desktop for each account

Every account gets the Waydesk desktop unless another is set, with one command:

$ sudo waydesk-admin users set NAME --desktop plasma

Or cosmic, hyprland, sway. The other desktops are ordinary packages of the distribution: install the one wanted, then give it to the account. What was tested, and where.

Waydesk desktop

The default: a shell, a launcher and a dock. Debian 13 and Ubuntu 26.04, amd64 and arm64. An idle session takes about 0.7 GB.
KDE Plasma

Tested on Arch with an Intel GPU, and on Debian 13. Install it from the distribution. An idle session takes about 0.75 GB.
COSMIC

Tested on Arch with an Intel GPU. Install it from the distribution. An idle session takes about 0.9 GB.
Omarchy (Hyprland)

Tested on Arch with an Intel GPU; Hyprland needs a GPU. An idle session takes about 0.75 GB.
ML4W (Hyprland)

Tested on Arch with an Intel GPU; Hyprland needs a GPU. An idle session takes about 1.0 GB.

An existing Sway or Hyprland setup can be kept: config check says whether it will work as a session. Omarchy and ML4W have been tried; other dotfiles have not.

Who it is for

who

A small team on one server

Each person gets a desktop of their own on a shared Debian or Ubuntu machine, with memory limits, and one RDP client is all they need.

who

Developers on a bigger machine

Work in a browser, an editor and a terminal that live on the server, from a laptop or a Mac, and pick the session up again where it was left.

who

Labs, courses and support desks

A ready desktop per account with a few applications, created with waydesk-admin users add, on an existing server.

who

Anyone on a slow or distant link

Image quality adapts to what the connection can carry, so a session across a long or lossy connection stays usable.

Memory, CPU and bandwidth

Most of the work went into not wasting what a server has. Every figure has its method on the measurements page.

slow or lossy links–□✕

Usable on lossy links

Each connection uses TCP BBR. On a distant link with about 4 % loss, throughput rose from 0.3 Mbit/s to 2 to 4 Mbit/s, and typing stopped arriving in bursts.

flow control–□✕

The video follows the link

Frames and bytes in flight follow the path; the video bitrate follows what the connection delivers, from 300 kbit/s to 10 Mbit/s.

H.264–□✕

H.264 for screens, on the CPU or the GPU

Screen-content mode, only the changed rectangles: about half the bandwidth of the camera mode. In software by default; with an Intel, AMD or NVIDIA GPU the desktop and the encoder move to it.

pointer–□✕

The client draws the pointer

The client draws it with its real shape, so it moves at once; only a change of shape arrives a round trip late.

memory–□✕

Memory limits

A memory ceiling per account, compressed swap, and new logins refused when the machine is full: 7 to 8 users with Chromium, Calc and VS Code open fit on 8 GB.

isolation–□✕

One session per account

Each account in its own session and systemd slice; the daemon has no privileges, and a small root helper starts sessions.

A local AI model shared by the accounts

A local model (Ollama, vLLM or another service) that every account reaches on localhost, so code and documents do not leave the machine. Waydesk does not install or run the model: it keeps the desktops off its card and shows who is using it. Recipes: a server that runs the model, and workstations that use it. A hosted model works too, without anyone sharing a login: one key per account behind a gateway on the server, with budgets and revocation (the recipe).

GPU roles–□✕

Desktops on one card, the model on the other

Mark the NVIDIA card for inference, and sessions render and encode on the Intel or AMD card instead. Measured with 8B and 14B models and up to 10 sessions: the model's speed did not change.

localhost–□✕

One model, every account

Any account on the server can call the model on localhost. There is no authentication and no per-account limit yet, so it suits a team that trusts itself.

status–□✕

See who is using it

waydesk-admin status shows the model, its video memory and an AI column with the connections each account has open. Connections, not tokens.

Applications

Wayland or X11, from the distribution or from Flathub.

X11–□✕

X11 applications run

Applications that only speak X11 run through XWayland, one server per account, closed to the others. Checked with CoreX, xeyes and GIMP.

Flathub–□✕

Flatpak

Flathub works as it is. Checked: Chromium, VS Code, LibreOffice Calc, Obsidian, Slack, GNOME Text Editor and GIMP.

windows–□✕

Window title bars

Title bars with minimize, maximize and close in the theme's colours (dark or light), soft shadows, and a dock that bounces while an app starts.

keyboard–□✕

Keyboard layout

The layout follows the client. Some keyboards map keys differently, such as a MacBook's through the Windows App: pick its layout in the Keyboard window, and the session switches at once.

Connecting by RDP

The RDP port listens on 127.0.0.1 only. waydesk-setup-admin asks how clients will connect: through an SSH tunnel (the default), from the local network, or over a WireGuard VPN that Waydesk sets up. Clients tried so far: the Windows App on macOS, mstsc on Windows 11 and FreeRDP. How to connect · VPN and security.

Install

1. Add the repository and check the key

$ curl -fsSLO https://waydesk.dev/apt/waydesk-repo.deb
$ sudo apt install ./waydesk-repo.deb
$ gpg --show-keys --with-fingerprint /usr/share/keyrings/waydesk-archive-keyring.gpg

The first download cannot be verified by the repository itself, so compare the key with this fingerprint (ed25519, expires 2029-10-21). If it differs, stop and report it.

C646 72B2 5ECD 4773 196C  3958 9D8E 8874 E676 17F4

2. Install, and make the first administrator

$ sudo apt update
$ sudo apt install waydesk
$ sudo waydesk-setup-admin       # asks how clients will connect; there is no default account or password
$ waydesk-setup                  # optional, as the account itself: choose browsers, office, developer and creative apps

On Arch Linux (x86_64 or Arch Linux ARM)

$ curl -fsSL https://waydesk.dev/arch/waydesk.gpg | sudo pacman-key --add -
$ sudo pacman-key --lsign-key C64672B25ECD4773196C39589D8E8874E67617F4   # the same key as above
$ printf '[waydesk]\nSigLevel = Required DatabaseRequired\nServer = https://waydesk.dev/arch/$arch\n' | sudo tee -a /etc/pacman.conf
$ sudo pacman -Syu waydesk-server
$ sudo waydesk-setup-admin

On Fedora 44

$ sudo curl -o /etc/yum.repos.d/waydesk.repo https://waydesk.dev/rpm/waydesk.repo
$ sudo dnf install waydesk-server       # dnf asks to import the key: compare it with the fingerprint above
$ sudo systemctl enable --now waydesk-helper.service waydesk.service
$ sudo waydesk-setup-admin

Arch and Fedora get the server and its sessions (plain Sway, or the desktop chosen for an account); the Waydesk shell, launcher and dock are Debian and Ubuntu packages. What was tested on Arch.
